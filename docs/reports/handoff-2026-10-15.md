## 5. Standing rules a successor must keep

- **Problem documentation first:** a docs commit before any fix.
- **Landing Loop:** commit → push main → CI → deploy → verify the staging
  commit → proof, including the four-part paper-healthy check.
- **No pushes during a tracer or a Dolt stop.** No `git commit -a`.
  gofmt only your own files.
- **Never print secrets.** Load credentials inside python only. Don't
  read the platform DB DSN, and don't run SQL against production Dolt.
- **Tracers** act only on computers they mint, and stop them afterwards.
- **Never touch:** node-a, ~/Mike or mike-* containers, a running guest's
  block device, or the untracked `sourcecycled`, `ograph-bench` and
  `cmd/desktop/frontend/`.
- **Product names:** Autopaper, Autoradio, Autoputer (never camel case).
  The four desks are Texture, management, engineering and research.
- **Node B:** ssh alias `node-b`, root via sudo, with owner consent for
  sensitive tasks. OVH API helper `ops-local/ovh_node_b.py`. The OVH
  `rescueSshKey` is set to `~/.ssh/id_ed25519_ovh.pub`, so rescue boot
  needs no emailed password.
