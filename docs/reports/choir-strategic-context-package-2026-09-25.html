1. Executive Summary & The Core Thesis

Choir is the automatic computer: a persistent place where agents, tools, notes, sources, and decisions work together — and where the work itself is the interface.

The generative AI industry is clustered around a single conceptual model: the agent is a digital worker, the computer is its tool, and a conversational chat thread is its interface to the human. Choir inverts this model: the multi-agent system is the computer. The objective is not to replace human workers with synthetic chatbots, but to build the computing environment required when autonomous intelligence runs continuously.

The Fundamental Tension: Computation now runs faster, longer, and across more parallel threads than any human can watch. Yet humans are still expected to supervise multi-agent runs through chat scrollbacks. Chat was designed for two humans taking turns; it completely collapses as a supervisory interface for autonomous, long-running agentic work.

Choir resolves this tension through a singular architectural breakthrough: versioned, human-editable shared state as the control plane. Autonomous agents continuously update the authoritative document representing the state of the work. Humans read that state directly. When a human edits a line or paragraph, that edit is not a prompt or comment—it is a control action that creates a new version and steers subsequent agent trajectories.

"Language is for intent. The document is for steering. When the work itself is the interface, humans supervise hours of agentic execution at a glance."

2. Product Architecture & The Functional Hierarchy

Choir is structured as an immutable, causal core that projects multiple synchronized user-facing surfaces:

1. THE EVENT TAPE Append-only immutable causal ledger. Every state mutation, prediction, approval, and message is recorded as a typed event with deterministic replay. ↓ 2. OBJECT GRAPH (OG) The living projection of authoritative current state. Agents and humans inspect, query, and modify this graph. ↓ 3. USER SURFACES Synchronized projections of the Object Graph: • Texture: Living, human-editable document surface (the workbench). • Mail: Permissioned agency in the real world (gated email actions). • Automatic Newspaper: Provenance-linked intelligence wire (scale). • Automatic Radio: 2-way spoken-word station & voice steering (attention).

The Four Product Surfaces

Texture On Staging

The Living Work Surface. Work is represented as an authoritative, versioned document. Sources, transcripts, data tables, and agent draftings sit inline. A human inspects the document and edits text directly; agents read the new revision and adjust their active tasks.

Mail On Staging

Supervised Agency in the Real World. An email agent operating under strict capability boundaries. It reads incoming mail, drafts responses, and monitors threads. Consequential actions (such as sending mail outside the sandbox) are strictly gated by human owner approval.

Automatic Newspaper In Refactor

Scale & Provenance (The World Wire). Continuous autonomous journalism tracking global developments. Every story is a Texture document backed by thousands of raw sources. Readers consume synthesized current state rather than raw agent chatter; every claim links to verifiable evidence.

Automatic Radio In Development

2-Way Participatory Voice Layer. An AI DJ mixing audio clips, YouTube segments, and text-to-speech summaries of the wire. Crucially, it is bidirectional: users listen, interrupt, contribute voice takes, and use spoken word to prompt 24/7 background agent workflows.

The Desktop Publishing Analogy: In 1985, desktop publishing (DTP) replaced physical typesetting by turning the computer screen into a direct WYSIWYG canvas. Choir does the same for autonomous AI: instead of managing agent swarms via command-line terminals or chat transcripts, the entire multi-agent computation is rendered into a familiar, editable desktop and document workspace.

3. Precommitment Records: The Engine of Reliability & Trust

Formerly designated as PICL (Predictive In-Context Learning), precommitment records represent Choir's core safety, alignment, and evaluation mechanism. In high-stakes work, black-box LLMs are liabilities because they act without committing to an explicit hypothesis or reasoning path.

PRECOMMITMENT RECORD WORKFLOW: 1. PREDICT: Before taking a consequential action, the agent writes an immutable record: "I predict action X will result in state Y because of evidence Z." 2. EXECUTE: The action runs inside an isolated sandbox or capability-bounded capsule. 3. ADJUDICATE: The actual outcome is compared against the precommitment record. 4. RESOLVE: The delta is logged to the tape. Correct predictions reinforce memory; incorrect predictions update beliefs and lower the system's operational risk.

Precommitment records serve three distinct functions across the product stack:

  1. In-Context Learning Without Retraining: The system accumulates empirical track records of what works and what fails across sessions, allowing prompt strategies and agent workflows to self-correct in context.
  2. Auditability for Regulated Enterprise: Banks, defense contractors, and healthcare organizations cannot deploy autonomous agents without deterministic audit logs. Precommitment records provide an unalterable proof of intent before execution.
  3. The "Box Score" Data Product: In public news and analysis, every forecast and factual statement is converted into a structured prediction with a resolution contract. Over months, this produces an ungameable, historical track record of institutional and speaker credibility.
Why Precommitment Records Beat Post-Hoc Explainability:
Post-hoc explanations ("Why did you do that?") are notoriously prone to rationalization and confabulation in LLMs. By forcing the system to precommit to its forecast, probability, and evidence before acting, Choir makes agent reasoning falsifiable and auditable in real time.

The Open-Source Paradox Resolved:
Open source is neither charity nor a developer vanity metric. It is the deployment answer for data sovereignty. Open source builds the trust and distribution; curated data feeds, managed cloud convenience, and on-prem FDE contracts capture the revenue.

The Compounding Advantage (The Moat)

Code is not the moat—models and frameworks commoditize rapidly. The durable economic moat is accumulated, user-owned work history and verifiable citation graphs:

  • Owned State: As models become faster and cheaper, the historical record of human edits, corrections, decisions, and precommitments becomes exponentially more valuable.
  • The Network Effect: Each user-owned computer publishes verified claims into the network; other computers query and cite those claims via API/MCP. More computers = more verified state = a smarter network for everyone.

7. The Deep Framing Synthesis: Reframing the Problem & Opportunity

The central intellectual challenge currently facing the pitch narrative is how to frame the opening problem without diminishing the radical scope of the solution.

The "Feature Trap" vs. "The Computer"

In startup pitching, conventional advice demands framing the company around an acute, daily "hair-on-fire problem." However, for platform breakthroughs (like Xerox PARC's GUI, Apple's Mac, or Choir's Automatic Computer), framing the problem at the symptom level creates a fatal trap:

  • If the problem is framed as "AI has amnesia," the listener expects a memory plugin (e.g., ChatGPT Memory or a vector database).
  • If the problem is framed as "AI hallucinates citations," the listener expects a search widget (e.g., Perplexity).
  • If the problem is framed as "reading long transcripts is tedious," the listener expects a collapsible chat UI.
"A small problem shrinks Choir into a feature on an existing chatbot. A problem that justifies an entirely new computer must be framed at the level of the machine itself."

The Four Paradigmatic Hook Formulations

To preserve the true magnitude of Choir while remaining grounded in felt human reality, the narrative can lean into one of four architectural framings:

1. The Category Error

"Why are we still using a messaging app to control autonomous intelligence?"
Chat was invented for two humans taking turns. Using chat to supervise autonomous multi-agent systems is like using a telegraph to operate a modern operating system. Autonomous work requires a persistent computer.

2. The Fundamental Inversion

"What if AI isn't an assistant you talk to, but the computer you think with?"
Managing an agent like an employee creates constant coordination friction. When the multi-agent system is the computer, living documents and audio streams are just native surfaces of that machine.

3. The Scale Asymmetry

"Computation outran human attention. What is the interface to govern it?"
When models run for 8 hours across 1,000 sources, human verification bandwidth is the absolute bottleneck. The winning interface must compress hours of agentic work into a 30-second inspection and steering gesture.

4. The Stateless Trap

"Why does intelligence get cheaper every month, but none of our work gets more permanent?"
Stateless chat traps work in disposable silos. Choir provides the persistent, user-owned state layer where accumulated work history, corrections, and precommitments compound in value over time.
