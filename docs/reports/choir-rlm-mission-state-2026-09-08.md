## The carrier boundary, honestly stated

We freeze the RLM boundary as system truth, not as a claim of completion. The intended boundary is that a desk sees one Go evaluation carrier, works with typed Go values, and stages consequential intents, while the host-side reducer remains the only authority that changes canonical state, advances mailboxes, mints receipts, settles terminal fate, freezes or revokes capsules, and records verifier decisions. The old JSON tools are retirement inventory, not alternate implementations. Before they disappear, every record-result, transaction, bundle inspection, verification, co-agent update, assignment fate, and terminal-report affordance must be classified as either an in-cell typed operation staging a reducer-owned intent or an obsolete path to delete.

The terminal outcome is not merely another tool response. The proven failure shape is a batch in which an evaluation and a terminal call coexist, a transient provider call identifier enters report identity or a digest, and a retry arrives as a different semantic command. The correction is a single terminal-outcome contract at the reducer boundary: the update packet is validated as a complete semantic proposition — assignment, attempt, actor, canonical computer identity, disposition, evidence, canonical payload — and either records one durable result and ends the loop or returns an explicit rejection a researcher can investigate. Provider call identifiers, retries, batch positions, and delivery receipts stay evidence metadata; they never become terminal identity. The researcher fallback is not a second committer but the path that explains an invalid packet, gathers evidence, and returns a new packet to the same authority.

Failure behavior splits in two. A compile error has not run a cell: it must surface as structured diagnostic feedback while preserving imports and definitions from prior cells. Runtime panic, timeout, worker death, or integrity failure poisons the interpreter, discards the staged tray, holds the inbox cursor, and starts the next cell from a fresh interpreter over the same durable snapshot. The system must never answer either case by silently diverting to the legacy one-shot worker — and the one-shot path's habit of burying the exact diagnostic under a generic wait error is itself a defect to remove in the unification. Compile feedback preserves the useful heap; runtime poison preserves durable truth and discards only the unsafe heap.

Plane four is the host-retirement plane, and its completion condition is not hiding a tool from a prompt but giving every named operation a typed replacement, moving every caller across, validating it in one durable command, proving idempotent replay returns the original receipt, and deleting the old path. The target is a real single-carrier surface, not a sealed catalog of six tools under a new name. In-cell completion removes the same-turn batch race; serialized reconciliation remains because it is what gives the result authority. The sealed overlay today still carries the evaluation primitive plus five model-visible JSON tools; the reducer still casts intents and advances the cursor through separate durability steps. None of that is the destination.

The word "host" retires everywhere, in docs as well as code. Launcher-process environment, guest kernel command line, platform content-addressed store, guest-core reconciliation, capsule guest namespace, activation route selection — each names one thing the old word blurred. The design, the cutover definition, the orchestration report, the product doctrine, and the standing questions all still speak the old word where precision matters most; the documentation pass leads, and code renames ride with the mission work so nothing new lands under the old name.

## Restore and identity

Restore is ordered first. A snapshot plus its immutable tail is the recovery object: the Dolt head is the address and materialized witness through which a computer is located and checked, a guaranteed projection base makes reconstruction tractable without becoming an alternate authority, and only events after the watermark replay. What exists today is the inverse — a fresh empty store replayed from genesis with the witness compared afterward and the base fetched opportunistically — and the historical restore references are explicitly forbidden in the current recovery mode. Promoting the imagined behavior is the zeroth mission because the rename and every self-development loop inherit its replay depth. Done means a restore completing in watermark-plus-tail time with the verifier's equivalence check passing against restored state, not a genesis reconstruction.

Computers keep their canonical identifier in every route, signature, and replay contract; display names travel alongside as a parallel UI field. Redacted email derives frontend-only from the session user; deterministic word-lists need a small stable helper; both are UI-only with explicit privacy policy. Substituting identifiers in wires or logs is out of scope.

Desk names are versioned protocol vocabulary, not labels. Profiles, capabilities, verb sets, Yaegi session selection, reducer aliases, prompts, frontend status, persisted runs, lifecycle records, assignments, mailbox destinations, agent-ID prefixes, digest domains, signed grants, evidence identifiers — the migration inventories every role-bearing field and sorts display-only from live-protocol from immutable-history. The hard cutover is live and forward-only but replay-aware: V1 tape keeps decoding under V1 rules with original bytes, V2 writers emit only the new vocabulary, unversioned legacy values are rejected at activation, and a versioned replay decoder exists because historic tape is evidence. Unknown roles must be rejected rather than falling through to broad authority, a hazard the current strict-equality check makes real. The rename lands early, after the settlement gate and before desk code mints further old-vocabulary artifacts — the narrowest point where a replay regression is identifiable without also debugging a carrier rewrite. Full genesis replay must be assumed until the restore mission proves otherwise.

## Desks and the research flow

Texture is the canonical structured-writing plane, and any Go interface for document trees, patches, diffs, source graphs, controls, and dispositions is acceptable only if the compiled reducer preserves the existing invariants: single writer, stale-base comparison, atomic revision-graph-identity commit, retry-preserved pending mutation, versioned compare-and-swap, fresh-but-not-replay wakes, per-document wake locking, atomic researcher opening. Engineering is the first practical carrier proof because its evaluation route is the shortest path to deleting residual terminal affordances; Texture's packet design develops in parallel and lands only when the host proof is complete. Management is a host-side activation, never an effects-capsule copy. Research starts maximally restricted: a no-search first revision usefully proves the gate stayed shut, and once search exists the search-to-checkpoint cadence is durable contract, not prompt instruction.

The conductor is not RLM and stays deterministic through this stack; its agentic future is deferred until it can receive the same single-carrier treatment with its own authority story. The prompt-bar twenty seconds are admission, commit, import, and dispatch overhead — no model call waits before the response — with the one-tape Texture handoff's synchronous lifecycle start, audit, run admission, and optional media fetch as the cost surface, dating to the early-August supervision landing while the handler itself is July-vintage. The mission profiles first: per-step roundtrips, redundant writes, N+1 reads, storage amplification per invocation, and the synchronous media fetch hiding in run preparation. Waste is removed before any contract relaxation; if async remains justified, the response narrows to a submission identity carried by a durable state machine the CLI and browser consume identically. The SSE banner is a separate stale-state bug over an auto-retrying stream: persistent error text with no clearing path, requiring status polling and terminal failure states independent of the banner.

Test drift is competing-contract drift and lands with the repair: conductor v0-only versus v1 expectations, exact `{text}` versus `{text, command_id}` bodies, synchronous materialization versus accepted submissions.
