What: `RadioInfo` (the `radioView` answer; `mobile/exact-package/interface/bar.json`, `BarState.swift`) lost 16 fields that no shared code and no native reader used: source, position, index, count, paused, speed, speedChoices, mode, micOpen, heard, holding, revised, blockProgress, next, kind, sources. Eight stay: title, playing, level, speedValue, micLevel (read by the contracts as `ri.<field>`) and sentences, sentenceIndex, progress (read by `radio-bridge.ts` through the `radioFacts` op, and `ReaderFeed`). `BarTracker.radioInfo` no longer takes `route` or `nextTitle`, which only filled the deleted fields. `exact.json` is regenerated by `gen-exact-interface.py`. A new `radio-info-fields.test.ts` names a reader for every field left, so a dead field added back fails it. The non-voice native ceiling falls from 3,127 to 3,084 lines.
Why: the move to Exact cannot finish while Swift computes values nothing reads. The parked `lane/bar-facts` found 19 unread; its sentence work is not on main, so three of the 19 (sentences, sentenceIndex, progress) are still read here and stay.
Proof: bun test, contract build, test web, the whole Swift suite and the boundary gate, run in the lane; not deployed or run on a device.
Replaced: the 16 fields and the Swift that computed them, and the Swift test assertions of only those fields (the clamp test now asserts the sentences of the clamped block).
Undo: revert the commit.
