title: a key that could not be read is not "no key": the reason is kept and the sign-in sheet is not offered for it
class: red
---
What: `api.ts` `keptSession` tells "no key" (null, only for a clean `found: false`) from "could not read" (a `SignedOutError` of reason `locked` or `unknown`, never `none`). The reason comes from the failing read itself: a source that answered `unreadable` is `locked`, a refusal whose message contains "no store here" (Exact's between-answers refusal, `door.rs:421`) is `unknown` and carries `noStore`, a malformed answer is `unknown`. The key state is asked again only when the source threw with nothing to say. `keyState` carries the `noStore` flag. A refusal from a let-go answer (`noStore`) stops quietly (`refusedHere`, texture-edit's `isLetGo`: the journal is kept, no `failed` label). The error is recognised one way, by name (`isSignedOut`). A shared pair, `unreadableWords` and `signedOutStatus`, words and maps it for the pages that showed sign-in or sign-out advice: Settings, Computer, Activity, Texture save, takes, content sync (offline), the radio programme post (transport), delete account (three answers, nothing posted for the third). `session-guard.test.ts` fails for any non-test `.ts` file that touches sign-in state without a listed decision, and for any `instanceof SignedOutError`.

The sign-in sheet: `au.signedIn` is false for a key that could not be read too, and the contracts opened the sheet on it (ask bar and microphone button in `spine.contract`, Record in `members-takes.contract`, Mail's ask in `members-mail.contract`). A locked phone after a restart could therefore be sent to sign in and get a new key written over a signed-in account. Now `account.contract` has one decision, `offerSignIn = acs.action == "signIn"` (the account's own answer: signed out and a refused key; never locked, unknown or a host with no sign-in), and every site that sets the sheet reads it. For `locked` the listener sees the existing locked banner and the tap does nothing; for `unknown` nothing happens; signed out opens the sheet as before. The first-run welcome card is not shown while the account is `locked` or `unknown`. `acs` is asked again every 3 seconds while locked or unknown (`rereadLocked`, `lockTick`), so a site cannot stick. `choirAuthState` answers status `unknown` for a no-store or thrown read, not `idle`; nothing reads `au.status`. `contract-signin-pin.test.ts` pins every contract line that reads `au.signedIn` or names the `"signin"` gate, each with a reason, so a new one is reviewed.

Why: the store works only while an answer runs (`door.rs:52`). A read from a let-go answer threw and was answered as "no key" for the `session` op. The trigger of the request storm is removed in another lane ([problem](../problems/a-signed-in-app-asks-the-server-for-the-changelog-about-forty-times-a-second-2026-11-28.md)). Three review rounds each found one more channel that held "signed in" as two answers; the approach changed to one decision point ([evidence](../evidence/key-read-refused-three-rounds-2026-11-28.md)).

Proof: bun tests `session-unreadable.test.ts` (U1 to U15), `session-reasons.test.ts` (every reason at every word and state site), `session-guard.test.ts`, `contract-signin-pin.test.ts`, `account-state.test.ts` (choirAuthState's four cases, the action of every state), `texture-edit.test.ts` T14b and T14c, `account-delete.test.ts` D6b and D6c. Not proved: no contract test taps Ask, Record or Mail's action with a locked or unknown account, because the web host skips `answer source` and cannot fake it; the sites are held by the pin and the derive checks. Nothing ran on a device.

Replaced: `session` answering `found:false` for a refused read; sign-in sheets opened on `au.signedIn == false`; page words that said sign in or out for any `SignedOutError`.

Residuals, not fixed here (from the evidence record and the reviews):
- With no store and Exact not between answers, `store.get` returns null, which reads as "no key" (`door.rs:53`). Not closed.
- If Exact rewords "no store here", a between-answers refusal reads as `locked` ("Unlock your phone"): safe, slightly wrong words, and it no longer stops quietly.
- A sign-out begun while the key is unreadable cannot name the key's digest, so its block lifts when the same key is readable again (pinned by U12). `beginSignOut` writes `blockedDigest` after an await, so an `abortSignOut` during that await is overwritten (older).
- Whether errors are ever copied across a boundary that breaks `instanceof` is not shown; recognising by name costs nothing.
- Where the account state is `noSignIn` or `noPasskey`, Ask, Record and Mail's ask now do nothing (they used to open a sheet whose sign-in could not work).
- The larger fix: read the key inside the answer that starts a piece of work and hand it on as a value, so nothing reads the store between answers.
- `contract-signin-pin.test.ts` pins lines of `members-settings.contract`, which another lane also edits: a conflict there is a rebase to resolve, not a defect.

Undo: revert the commit.
