What: `mobile/scripts/proof-key.sh` is new, and `proof-real.sh` uses it. The proof mints a disposable key with the QA key (`POST /auth/api-keys`, three hours), writes it as `choir.key` in Exact's scratch secret store (not its id: with an id the native sign-out compares it with the Keychain, which holds none in an agent drive, and refuses the sign-out as superseded) in the simulator's container (files 0600, directory 0700), and removes the stamp, the sign-out marker, the pending-revoke list and any computer id so the next launch does not wipe or sign out. Right after the warm-up drive it asserts the account page says Signed in and the console says `api: session found=true key=true`, else `PROOF FAILED at sign-in: the app is signed out`. A refused mint stops with `PROOF FAILED at sign-in: the test key may not mint keys (<status>)`. The signed-out drives clear the seed and assert they are signed out. An exit trap revokes the minted key by id and says loudly, with the id only, if it cannot. The key is never on a command line (curl reads headers and body from files), in a variable, in a log or in an `sh -x` trace. The `proof-key` copy into Documents is gone. `sim-device.sh` now picks the newest runtime that supports the iPhone 18 Pro from `simctl list -j runtimes` and fails naming the device type when none does.

Why: since 5721a63cd the key lives in shared code, which in an agent drive reads Exact's scratch store and not the Keychain, so the proof ran signed out for five days and nothing noticed. The QA key must not be seeded itself: the sign-out drill revokes the key the app holds. Plan: docs/design/proof-sign-in-after-the-key-moved-2026-11-28.md, option A.

Proof: five real runs against staging on 2026-11-28, the last on 776291faa (main 954102fc7 plus this lane): the mint is allowed, Exact reads the placed file, the app launches signed in, 29 drives pass signed in, the sign-out drill signs out, and the key is revoked at exit. What the runs changed in the script: a killed proof now still revokes its key (the first run was killed by a time limit and left the key live; it was revoked by hand); the signed-in check also reads the simulator's console (the app logs its session line once, and a late drive missed it); the key is seeded without its id; the old edition picks file is expected gone after launch (native removes it at every launch since 096899556). `sh mobile/scripts/test-proof-helpers.sh` passes over fake `curl` and `simctl`. Not proved: the app's own server revoke at sign-out (no id is seeded). The proof still fails on two findings in the app, which are real and recorded: the sign-out leaves its marker and stamp (`account: wipe radio failed`), and `radioHold` runs over Exact's 100 ms turn. What the first signed-in run found is in [the request storm record](../problems/a-signed-in-app-asks-the-server-for-the-changelog-about-forty-times-a-second-2026-11-28.md).

Replaced: the `proof-key` file in Documents and the native import it fed (`ProofKey.swift` stays, unused by a drive, until owner decision D6).

Undo: revert the commit. The QA key is untouched; the proof only ever holds a disposable one.
