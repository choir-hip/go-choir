title: Android offers only the controls its module answers
class: orange
---
What: shared code holds, as data, which native ops each host's module answers (`mobile/AutoradioLab/native-answers.ts`: an `android` row equal to the `when` cases of `AutoradioModule.kt`; any other platform, iOS, macOS, web and "" before the first answer, has no row and answers everything). `spine.contract` reads it once by `exactPage().platform` (`nans`, `opAnswered`, `canSpeed`, `canAsk`, `canHandsFree`, `canTalkCancel`, `sendOffered`); no control tests the platform itself. A control whose op is not answered is not offered: the speed row of the Autoradio page (`radioSpeed`), the bar's microphone button (`choirHandsFreeToggle`), its Cancel (`choirTalkCancel`), its Send for a question, mail's "Summarise this thread" and the Texture list's "Make your edition" (all `choirAsk`). On Android the bar's field says "Open a web address..." and, while typing, "This phone does not answer questions yet. A web address opens in the app."; an address still opens in place; a question stays in the field and is not sent. When Kotlin answers an op, the commit adds its case and its name to the table (a test fails until it does) and the control appears with no contract change. The web host is as before: it has no row, so it still offers every control. A platform not yet known (`""`, before `exactPage().platform` first answers) answers nothing native: no guarded control is drawn, a typed question stays in the field and is not sent, no sentence is shown, and a web address still opens (that path is shared code, `queueAct`). An unknown future platform string answers everything. The one accepted difference on iPhone and web: the guarded controls appear with the host's first answer instead of the first frame; Exact says the platform is known "from the first frame" (`contract-for-agents.md:6545`), and the account card already waits on the same fact (`account.contract:47`, `acs` is `unknown` until it), so no new visible flash is expected; not measured on a device. No Kotlin, Swift or interface change. The full list of ops is in `docs/evidence/android-ops-and-controls-2026-11-28.md`.

Why: the control was drawn and did nothing, and a typed question was cleared and dropped. The owner has not chosen between "Kotlin answers them" and "do not offer them"; this is the conservative default. Voice pages (voice cards, voiceprint, takes, Voice and models) have the same defect and are not changed; they are named in the evidence file.

Proof: tests first, seen red (`android-controls.test.ts` K1 to K5 failed), then green. K2 asserts the Android row equals the Kotlin `when` cases and that every interface name has a Swift handler. `android-controls.test.contract` A1 runs on the web host (no row: mic, Send and speed as before). The harness cannot set `exactPage().platform` (`prefer` has no platform), so the Android row is proved by the table test and by reading the contracts' guards, not by driving the Android bar. The iPhone path is A1, K6, and `bar-url.test.ts` S2 and S3. Not proved: any of it on a phone.

Replaced: the speed row, the microphone button, Send, the mail button and the Texture card drawn on Android with no answer behind them; the bar line "The radio answers aloud" on a phone that does not.

Undo: revert the commit. Nothing is stored.

No native code: the list is shared data kept equal to the Kotlin module by a test. Exact has no way to tell a contract that a host left a package op unanswered (`contract-for-agents.md:4453-4459` lists only `"web"` in `substitute.unsupported`; `NotSupportedError` becomes the default with no mark), and a native report would be a new interface name past the boundary ceiling, which only falls. So the table is in `native-answers.ts` and `android-controls.test.ts` K2 fails when Kotlin gains a case the table lacks. `scripts/autoradio-native-ceiling.txt` stays at 12 names.
