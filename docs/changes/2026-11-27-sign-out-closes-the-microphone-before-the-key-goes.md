What: the phone's sign-out now closes the voice before it deletes the key, and a turn cannot outlive it. One gate, `TurnGate`, holds all its sign-out state under one lock and never calls out to the key store while deciding. "A sign-out is running" IS "the sign-out task slot is occupied", read under the lock that guards the slot: there is no flag that anything sets or clears separately. `TurnGate.signOut(_:)` is the ONE way the gate shuts (it creates the task, stores it and moves the epoch, all inside the lock); the task's own last act empties the slot under the same lock; `ChoirApp.beginSignOut()` is its only caller and `signOut()` is `await beginSignOut().value`. No public symbol can shut the gate without the sequence that reopens it. The gate shuts at the sequence's first statement: `ModelsEntry.swift` is untouched from main (the op's handler is not on the main actor, where `AutoradioModule.current` lives, so a synchronous decision there was not possible without a latch), which leaves a known window of one actor hop between the native op arriving and the gate shutting. A signOut op that returns early (superseded key id, no module, no `choir`) never shuts it. `LabRuntime.closeVoiceForSignOut` then ends the engine's listening and turn inside one actor turn before any await (`TurnEngine.endForSignOut`: hands-free off, enrolment tap cleared, turn and pipeline cancelled, voice cut), drops a take in hand, and moves the session off the microphone, bounded to 2 s: a move that fails (`SessionCoordinator.reapply` now says so, including when another caller's move failed first) or does not answer is not waited for, and the microphone is closed the direct way (`LabRuntime.stop`, which the next play or question starts again through `ensureEngine` / `startRequest`). Only then the old steps run, in main's order: playback stops, shared code gets up to 5 s to post that it left the air with the old key still held, the key is deleted, the wipe runs. Every turn entry (typed, hands-free commit, button) captures the epoch and asks again at the last points before anything leaves the phone: after its waits, in `runTurn`, at the start of the pipeline, after the position is read, before the desk request, before each write to the conversation and each hand-off to speech. The turn's epoch also travels with every request its tasks make (a task-local set where the pipeline starts), and `ChoirClient.request`, the one native key read, reads the key under the gate's lock and refuses a request of an older epoch, so an old turn that reaches it after a fast sign-out and a new sign-in cannot go out under the new account's key; a request no turn made is refused while a sign-out runs. The places that open the microphone refuse while the flag is up: `HandsFreeSwitch.set(true)` (the one path to "on", checked under the switch's own lock, which sign-out's `set(false)` also takes, so a take's give-back that races sign-out cannot reopen it), `SessionCoordinator.setRecordingTake(true)`, `TakeSession.start` (at entry and after each await), `TurnEngine.handsFreeSet(true)` and the enrolment tap. A second `signOut` joins the running task; the slot is the state, so one that arrives at the end either joins it or starts its own, never one that has finished. The close also clears a take's recording state itself, awaited, before the session move (a take's own give-back is a Task nobody waits for), and counts the move as done only when the coordinator's resulting state has the microphone closed, read from the coordinator, not from `reapply`'s success. A refusal by the epoch in `hfCommit` returns without resuming playback, and `runTurn` re-checks after `addressing.decide` before it creates the pipeline. Not changed, kept exactly as on main: the key is deleted and the wipe runs unconditionally, so a sign-in that lands while a sign-out runs is destroyed with the old one (problem record, item 5); where the key lives; shared code's sign-out.

Why: after the first round (afd7d78ff) three reviews found the rest: a take's give-back reopened the microphone, a turn suspended in a wait resumed past an entry-only check, a take could start during sign-out, an old turn's request could carry a later account's key, and a gate that remembered who left could stick shut. This round removes what would not be correct: natively there is no event that says a key was stored (a sign-in is shared code writing the Exact secret, `keepKey` in `app-signin.ts`; native's ops are `signOut`, `wipe`, `accountStores` and the read-only `keystate`), so the gate keeps no copy of "who is signed in" and no identity: after the sequence ends, whether a turn goes is what the module's `keyPresent` reader says, as on main. The supersede rule of the second round (delete only the key sign-out began with) is removed: it left the old account's native stores readable by the new account and made shared code drop the old key's pending revoke. A kill leaves: before the key is deleted, signed in with the microphone off (hands-free is never kept across a launch) and shared code's pending marker finishes the sign-out; after it, signed out, and the marker finishes the wipe.
