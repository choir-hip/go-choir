# An answer is let go: fetches after an await

A source's answer (a resource, a derive, a mutation's send) may `await` and then fetch or call a native module, but only while that answer is still the one asked for. When the same resource is asked again with new arguments (a pulse every second), or a mutation is sent again, the older answer is **let go**: its next fetch is refused with "the answer was let go before this fetch" (`js/src/fetch.js`, `if (call.letGo)`; the same rule for the host's path in `host/web-js/ts-fetch.js`, `letGo` and `answers`, line 352). A fetch begun from work no answer waits for fails as "called from background work" (`js/src/fetch.js`, `call === background`) or "outside an answer" (the `!call` branch above it), and `native.call` likewise (`js/src/prelude.js`, `currentCall === background`). So a resource that is asked often must only read (one call, no chain of them) and say what work is due; the work, with its several awaited calls or a long fetch, belongs in a mutation, which stays until it is done. Every `void asyncCall()` is such background work. In this app: `radioPulse` reads, `radioHold` and `radioWrite` work (`mobile/AutoradioLab/radio-bridge.ts`), and `radio-pulse-rule.test.ts` fails when the pulse fetches or pumps, or a new `void` call appears unreviewed.

Once-a-launch work belongs to a mutation and its outcome is kept as a value, never as a promise other answers await: a source that starts it and is let go hands every later answer its refusal (`docs/problems/shared-settle-promise-fails-every-request-2026-11-25.md`, `docs/problems/radio-restore-empty-after-let-go-2026-11-25.md`). A refused read (`storage.readFile() called outside an answer: it was never run`) is not an absent file: only `ENOENT` is. A read that keeps failing as the disk's own failure is given up after a bound (`RESTORE_TRIES`; at once for `denied`, `unsupported`, `bake`), the file moved aside, never retried for ever. A refusal is not a server's or a disk's failure either, so it is never counted toward a backoff (`mobile/AutoradioLab/refused.ts`; `refused.test.ts` holds its strings against the pinned source, including the in-flight "the answer was let go before this reply"). A timer armed in such work throws once its answer is let go or has replied; the run sheet store arms no retry timer (the pulse calls for the next post). The timers left on the radio's paths: `settlePending`'s 50 ms poll at sign-out (not safe if that answer is let go: the sign-out rejects before the store's wipe), and in `radioWrite` (one at a time, a mutation) the writer's ask deadline and the 3 s bound on story texts (a let-go write abandons its ask either way). And a fact the contract already reads (the deck's state, `ds`) is handed to the source as an argument rather than read again over the native bridge inside it.
