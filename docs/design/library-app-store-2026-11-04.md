# The Library as an app store (2026-11-04)

Owner review on a phone, 2026-11-04: "For an app to get into the library, it needs to have screenshots. It needs to be installable. We shouldn't be showing all this metadata ... It should show the email address of the account that made it. And you need to be able to see the screenshots ... Remember, this is an app store." Then: one level, not two ("as soon as you look at that app, you should be able to see the information about it"); precommitments stay, readable; metadata hidden; no Base image tab.

## Rules

1. **Screenshots gate the listing.** A release with no screenshot is refused at publish (`screenshot_required`, 422) at three places: the guest release-draft route, the proxy before any write, corpusd. A video alone is not a screenshot. The catalog lists only releases that have one; its history drops the others for every reader but the publisher (who keeps them to withdraw). Nothing is deleted; a direct read of a stored release still answers, and install of one by id is unchanged.
2. **The maker is shown by their public Choir address.** The Library shows `<NNN>@choir.news` (the account's numbered address: users `000`, `001`, ... zero-padded to three digits, test accounts in `[10,000,000, 100,000,000)` as plain digits), never the account's sign-in email. maild owns the addresses; the proxy asks maild's host-internal, read-only lookup `POST /internal/maild/public-addresses` (loopback host-service callers only, the same gates as `assign-numbers`, at most 100 ids) for the owners of the releases actually present in the answer, and adds `publisher_address` and `own` (`internal/proxy/packages_publisher.go`, cached a minute, found addresses only). It is display-only: corpusd and the record never hold it. A request parameter is never resolved, so a track with no visible release shows no address (Devin B1). The lookup returns the account's *public address*, not "its number": today that is always the numbered one; later an account may choose one of its own addresses as public and the Library picks it up unchanged.
3. **No fallback; maild is a hard dependency.** If maild cannot answer, the catalog, history and release reads fail with 502 `publisher_address_unavailable`. A listed release whose publisher has no address is a defect, logged and named in a 502 `publisher_address_missing`. Publishing requires the publisher's account to have an address (checked at the proxy before the draft; 422 `publisher_address_missing`, or 502 `publisher_address_unavailable`), so a listed release always has one. Privacy fact: publishing makes the account's Choir address visible to every signed-in user on the app's card and page; the real sign-in email is never shown. These are real receive addresses on the public receive policy, so mail to them is routed.
   - **Gap found and fixed:** nothing numbered test or ephemeral-domain accounts: auth's reconcile filtered them out of the user sequence and only `maildctl` reserved and bound test numbers by hand. Auth now sends them to maild's assign route as `test_owner_ids`, and maild's `AssignTestUserNumber` gives each a test-range number at creation (the reconcile backfills existing ones; accounts that already have a number keep it).
   - Future, not built: email becomes an app agent; paid users register other addresses (`<myname>@choir.news`, `custom@domain.com`) or integrate Gmail, and may choose one as their public address.
4. **Card and page.** One card per app and maker: thumbnail (first screenshot), name, one-line description (the manifest's display description, flattened to one line and derived by the host at publish from the manifest it verifies; it is kept in the release object's metadata and never in the record, so the record format is unchanged, a revert is a true revert, and no publisher can claim a description), maker's Choir address, "Updated Nov 4". Tapping opens one page: name, address, description, Install / Update / Installed + Uninstall, a swipeable screenshot strip (tap to enlarge, the video inline), the precommitments in words ("Predicted 88% likely", "Came true"), and a collapsed "Version history" labelled "Version 2, Nov 4". No id, track, computer or metadata panel appears in the user view.

Mutation classes: server and publish gate red; frontend orange. Rollback is a revert (screenshot-less releases reappear in the listing; none were deleted). Rollout is by ring with no switch.

Install state belongs to one maker (Devin and DeepSeek round 1, B1): the Library resolves each installed release to the track it was published on, so maker A's installed `files-next` is not maker B's. B's page offers no Update and no Uninstall of A's app, notes that another maker's version is installed, and its Install confirm says it replaces it. Update is offered only to a newer version of the same maker's app. An installed app that is no longer listed stays uninstallable from an "Installed on this computer" section of the shelf, driven by the computer's install list (the install system's own state), not the catalog.

Residuals: the display name is the package name (the record carries no title). A catalog read costs one record read per visible listing plus one maild lookup per distinct maker (cached a minute). An owner who installed a pre-rule, screenshot-less head sees the newest screenshot-bearing release as the head, which is older: no Update is offered to an older release. A store read error in the catalog now fails the read (500) instead of hiding the app.
