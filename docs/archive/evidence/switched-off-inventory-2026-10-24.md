## Reading this

- **Ids** (A1 to E13) are stable handles for the wave plan below. Section A is the computer settings, B the vmctl host selectors, C the guest image, D host services (mostly already on, listed so nobody re-checks them), E Go-side switches that nix does not set, F the frontend.
- **Staging value** is what the repo shows: the nix value, or the code default when nix does not set it. Computer settings are per-computer rows in the object graph, so their value is not in the repo; the ledger value is quoted with its date.
- **Proof status**: *proved* (a ledger line or evidence file shows it on staging), *partly proved* (some steps), *never turned on*.
- **Class** is the CLAUDE.md mutation class of the flip itself, not of the feature's code.
- Mechanics: a **setting act** is `PUT /api/computer-settings` by the owner's key (no deploy). A **host selector edit** is a `nix/node-b.nix` change and a deploy; the computer picks it up at its next cold boot, since boot arguments and the credential disk are in the launch-config hash. An **image env edit** is `nix/autoputer-vm.nix` and a deploy.
