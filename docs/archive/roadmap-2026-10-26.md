## Part 2. Handoff for an agent without this session's context

Read in this order: [CLAUDE.md](../../CLAUDE.md) (the operating contract),

### 2.1 What to do first

Close the loops in 1.2 in table order, one at a time. Prefer landing,
proving and recording over starting anything. If a loop's next step needs
a red change that has not passed its review, do not land it; record where
it stands in the ledger instead.

### 2.2 The landing path (every behavior change)

1. Work in a worktree under `~/Dev/lanes/`, on a `lane/<name>` branch.
   Never edit the owner's checkout `~/Dev/go-choir` (it holds the owner's
   `go.sum` change and an untracked `scratchpad/`).
2. Tests first, in their own commit, then the code. End commit messages
   with the attribution lines the session gives.
3. Cheap checks before any review, all of them:
   `scripts/check-v1-writer-purity.sh`, `scripts/check-decode-roots.sh`,
   `scripts/check-test-hang-guards.sh`, `scripts/selftest-guest-token`,
   `go build ./...`; `go run ./cmd/lockscope -check cmd/lockscope/baseline.txt`;
   `.github/scripts/deploy-impact-classify-test`; and
   `go test ./internal/agentcore -run TestReleaseWitness`. When `nix/` or
   the flake changed, `nix eval --raw .#nixosConfigurations.go-choir-b.config.system.build.toplevel.drvPath`
   and the same for `go-choir-autoputer-vm`.
4. Review by tier (CLAUDE.md, Mutation Classes): none for green and yellow;
   one Devin seat for orange and switched additive red; Devin plus
   DeepSeek for red where a defect would be silent or irreversible. The
   launcher is `bash ~/Dev/lanes/_runs/mkdelta.sh N lane/X <old-sha> <prev-bunch> "title" "checks" [all]`;
   outputs land in `~/Dev/lanes/_runs/bunchN/`. The last number used
   today is 334.
5. The heavy test mirror runs on the agents VM:
   `ssh choir-agents 'cd ~ && (nohup ./ci-mirror.sh NAME origin/lane/X >/dev/null 2>&1 </dev/null &)'`;
   read `~/mirror/NAME.result` for `RESULT PASS <sha>`. It does not run
   every CI ratchet, so step 3 still matters.
6. Land by cherry-picking onto `origin/main` in a train worktree, re-run
   step 3, check the merge base is `origin/main`, then `git push origin HEAD:main`.
7. Watch CI with the FULL commit SHA (`gh run list --commit <full sha>`),
   then staging identity: `curl -s https://choir.news/health | jq -r .build.commit`.
8. Run the deployed proof named by the loop, then write a ledger entry
   (read `date -u` first) and update the problem or design doc's status.

Docs-only commits do not deploy. Anything outside the classifier's ignore
list redeploys the host and refreshes every active computer, so batch code
landings.
