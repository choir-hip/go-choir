## 4. Where the existing web policy disagrees with the code

1. Cookies: the policy names two; the code sets four (section 3).
2. Providers: the policy names Bedrock, Z.AI, DeepSeek, Xiaomi, Fireworks and OpenAI. The live pools name River, Synthetic, Devin, OpenCode, OpenRouter, ChatGPT and Bedrock. Search providers are not named at all.
3. "No embedding service": an embedder runs on the host.
4. Children: the policy says under 16. The shipping brief and the App Store rating answer say 13 and 16+. They must be one rule. **Settled 2026-11-23:** the minimum age is 16 everywhere.
5. Contact: the policy names a mailbox on choir.news. Use that one address everywhere, or replace it (CONTACT_EMAIL in these drafts).
6. Retention: the 90-day figures have no job behind them in the code read.
7. Deletion: the policy says erasure on request by email; the app will say deletion in the app. Both must describe the same thing.
8. Hosting: "United States" is not in the repo.

## 7. Where an account's personal data lives, and whether the deletion reaches it

Written 2026-11-24 with the deletion build (lane `account-delete`; read from the code, not run on the deployed host). "Reached" means the purge removes it 72 hours after the request, or changes it as stated. Everything in the third column is for the privacy policy; a row that says "not reached" is named so the policy does not promise more. The receipt (`account_deletion_receipts` in auth.db) holds a receipt id, the job id, a hash of the opaque user id, the request and purge times and counts per step; no email, no content.

At once, when the person confirms (before the 72 hours): every session and key of the account is revoked, its computers are stopped, its takes are not served, its sign-up address stays reserved, its passkeys stay so that signing in can cancel.

| Where | What it holds | Reached? |
